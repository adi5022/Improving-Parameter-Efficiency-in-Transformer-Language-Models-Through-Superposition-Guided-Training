## Technical details
- Run seeding: the run seed seeds init (`torch.manual_seed`) and the data generator, so runs differing only in γ share init and data (paired comparison). Test set: separate fixed seed 10,000; 100 × 2,048 samples, chunked.
- Saved per run: config, W, b, row norms, train-loss log every 100 steps, test loss, ϕ½, ϕ₁, mean squared overlap (all rows; rows with norm > ½), timing, device, torch version, git commit.
- Analysis: yardstick L*(m) = min over γ of seed-mean test loss (biased slightly low, noted in code); `equivalent_width(loss)` by log-log interpolation of L*; least-squares exponent fits with s.e. and per-seed exponents; gates G0.1–G0.3 from draft thresholds in config; G0.4 relative s.d. table.

## Problems and limitations
- Measured time per run (≈ 1.3 min, stand-ins) is above the earlier 2–4 h total estimate; both grids now ≈ 4.5–5 h.
- CUDA kernels are not bitwise deterministic; seeded reruns may differ in the last digits (CPU runs are exactly reproducible, tested).
- The reference has no test loss and no seeds, so "reproduction" is judged by the gates (regimes, exponents), not by matching numbers.
